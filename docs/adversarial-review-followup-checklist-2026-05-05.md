# 对抗性审核后续工作清单（执行版）

日期：2026-05-05

## 使用说明

这是一份可直接执行的后续任务清单。每项任务都补齐了前置条件、执行步骤、对抗性检查点、完成证据、失败判定和失败后动作，目标是让后续推进不再依赖口头解释。

统一规则：

1. 每完成一项任务，必须同步更新 `progress.md`、`findings.md`、`task_plan.md`、`docs/task-resume-log.md`。
2. 所有验证都必须覆盖正常路径、取消路径、失败路径、恢复路径、重复执行路径。
3. 在真实 CAD 人工交互验证完成前，不得写“可提交”“可交付”或“0 bug”。

## 任务 1：完成 `TB-Toolbox` 真实交互验证

- 优先级：`P0`
- 是否阻塞提交：`是`
- 前置条件：
  - 已准备真实 AutoCAD 宿主
  - 已准备至少 1 份正常图纸和 1 份非标准路径下的图纸
  - `TB-Toolbox/load.lsp` 可被加载
- 执行步骤：
  1. 加载 `TB-Toolbox/load.lsp`
  2. 执行 `TBHELP`
  3. 执行 `TB`，打开后正常关闭
  4. 再次执行 `TB`，验证重复打开关闭
  5. 执行 `TBSETTING`，修改并保存一项设置
  6. 重新打开 `TBSETTING`，确认设置已生效
  7. 在 `TB` 或 `TBSETTING` 打开过程中测试 `Esc`、直接关闭窗口、重复调用
  8. 在非标准图纸路径下重复以上步骤
- 对抗性检查点：
  - DCL 路径是否依赖当前图纸目录
  - 取消或关闭后是否遗留半初始化状态
  - 重复打开是否出现资源未释放问题
  - `CMDECHO`、`OSMODE`、`CLAYER` 是否被污染
- 完成目标：
  - `TB` 与 `TBSETTING` 在真实环境中稳定可用
  - DCL 资源定位和释放行为闭环
- 完成证据：
  - 宿主版本
  - 测试图纸名称
  - 每一步的结果记录
  - 若失败，附报错信息或截图
- 失败判定：
  - `TBHELP` 不可调用
  - `TB` 或 `TBSETTING` 无法打开
  - 关闭或取消后环境变量未恢复
  - 重复执行出现异常或资源泄漏迹象
- 失败后动作：
  - 记录失败步骤和宿主信息
  - 归类为 `DCL 路径问题`、`资源释放问题`、`环境恢复问题` 或 `重复执行问题`
  - 新建修复子任务，修复后必须复测全套步骤
- 预计工时：`0.5 天`

## 任务 2：完成 `DiffCheck` 真实交互验证

- 优先级：`P0`
- 是否阻塞提交：`是`
- 前置条件：
  - 已准备 `A.dwg` 和 `B.dwg`，两者存在少量差异
  - `DiffCheck/DiffCheck.lsp` 可被加载
- 执行步骤：
  1. 加载 `DiffCheck/DiffCheck.lsp`
  2. 执行 `DFC`，跑完一条正常差异检测路径
  3. 执行 `DFC`，在第一次选择阶段直接回车取消
  4. 执行 `DFC`，第一次选择成功，第二次选择阶段取消
  5. 执行 `DFC`，在 `REVCLOUD` 相关阶段按 `Esc`
  6. 执行 `DFCC`
  7. 再执行一次 `DFCC`
  8. 对每次操作执行一次 `UNDO`
- 对抗性检查点：
  - `REVCLOUD` 阶段是否卡住
  - 取消后是否存在未闭合 `UNDO`
  - 当前图层、对象捕捉、系统变量是否恢复
  - 重复清理是否报错
- 完成目标：
  - `DFC` 和 `DFCC` 在真实图纸上的正常、取消、清理流程均闭环
- 完成证据：
  - 正常路径结果
  - 取消路径结果
  - `UNDO` 验证结果
  - `DIFF_CLOUD` 图层和云线结果记录
- 失败判定：
  - `DFC` 正常路径无法完成
  - 取消后命令卡死或环境污染
  - `DFCC` 重复执行报错
  - `UNDO` 无法正确回退
- 失败后动作：
  - 明确失败在 `选择阶段`、`云线阶段`、`清理阶段` 还是 `恢复阶段`
  - 若与 `REVCLOUD` 相关，单列兼容性修复任务
  - 修复后必须回归正常路径和三条取消路径
- 预计工时：`0.5 天`

## 任务 3：完成 `SyncBlock` 真实交互验证

- 优先级：`P0`
- 是否阻塞提交：`是`
- 前置条件：
  - 已准备包含多个相似块、属性和不同图层颜色的测试图纸
  - `SyncBlock/SyncBlock.lsp` 可被加载
- 执行步骤：
  1. 加载 `SyncBlock/SyncBlock.lsp`
  2. 执行 `SyncNow`，完成一次正常同步
  3. 执行 `SyncNow`，主对象选择时直接取消
  4. 执行 `SyncNow`，主对象选择非块对象
  5. 执行 `SyncNow`，主块选择成功，目标选择阶段取消
  6. 构造异常目标块，执行 `SyncNow`
  7. 连续执行两次 `SyncNow`
  8. 每次完成后执行一次 `UNDO`
- 对抗性检查点：
  - `CopyObjects` 是否稳定
  - 异常目标块是否只被跳过而不破坏正常块
  - 重复执行后是否出现幽灵对象
  - `UNDO` 是否能独立回退单次同步
- 完成目标：
  - `SyncNow` 的正常路径、非法输入路径、异常目标路径和恢复路径全部闭环
- 完成证据：
  - 主块名称
  - `Synced` / `Skipped` 输出
  - 重复执行和 `UNDO` 结果
  - 若失败，附异常目标块特征描述
- 失败判定：
  - `CopyObjects` 报错
  - 目标块损坏或被删空
  - 重复执行后块定义异常
  - `UNDO` 无法独立回退
- 失败后动作：
  - 区分为 `COM/CopyObjects`、`目标块解析`、`重复执行`、`回退失败` 四类问题
  - 若为兼容性问题，联动任务 6
  - 修复后必须复测正常、非法输入、异常目标、重复执行四组场景
- 预计工时：`0.5 天`

## 任务 4：完成至少一个兼容 CAD 宿主的关键路径验证

- 优先级：`P0`
- 是否阻塞提交：`是`
- 前置条件：
  - 已选定至少 1 个兼容宿主，如 BricsCAD、GstarCAD、ZWCAD 之一
  - 已有 AutoCAD 对照结果
- 执行步骤：
  1. 在兼容宿主中加载 `TB-Toolbox/load.lsp`
  2. 验证 `TBHELP`、`TB`、`TBSETTING`
  3. 在兼容宿主中加载 `DiffCheck/DiffCheck.lsp`
  4. 验证 `DFC`、`DFCC`
  5. 在兼容宿主中加载 `SyncBlock/SyncBlock.lsp`
  6. 验证 `SyncNow` 的关键正常路径和一条取消路径
  7. 与 AutoCAD 结果逐项对照
- 对抗性检查点：
  - COM 不可用时是否走到安全提示分支
  - 兼容宿主是否存在额外交互要求
  - 恢复路径是否与 AutoCAD 一致
- 完成目标：
  - 明确至少一个兼容宿主的实际可用范围
- 完成证据：
  - 宿主版本
  - 功能对照表
  - 通过 / 降级 / 阻塞分类结果
- 失败判定：
  - 关键命令无法执行
  - 恢复路径行为失真
  - 与 AutoCAD 相比存在未解释的宿主差异
- 失败后动作：
  - 为每个阻塞项标注“修复 / 降级 / 放弃”
  - 不允许只记录“兼容性有问题”而不分类
- 预计工时：`0.5 天`

## 任务 8：决定是否将 TB 命令层整体切换到 `uc:guard-*`

- 优先级：`P1`
- 是否阻塞提交：`否`
- 前置条件：
  - 任务 7 已完成
- 执行步骤：
  1. 基于任务 7 的结果列出仍在用旧入口的命令
  2. 评估迁移收益、风险和迁移范围
  3. 拆出最小迁移批次
  4. 形成“迁移 / 不迁移”的明确决策
- 对抗性检查点：
  - 迁移后取消路径是否可能双重恢复
  - 迁移后 `UNDO` 生命周期是否可能错位
  - 迁移是否会引入嵌套保护区问题
- 完成目标：
  - 对 TB 命令层保护机制形成明确路线
- 完成证据：
  - 决策记录
  - 若迁移，给出分批计划
  - 若不迁移，给出边界和理由
- 失败判定：
  - 只讨论方向，没有落成决策
  - 迁移范围不清晰
- 失败后动作：
  - 回到任务 7 继续补证据
- 预计工时：`0.25 天`
