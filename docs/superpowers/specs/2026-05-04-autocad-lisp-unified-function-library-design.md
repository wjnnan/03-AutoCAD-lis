# AutoCAD Lisp 统一函数库重构设计

**目标**

在不破坏现有命令入口的前提下，以 `atlisp-lib` 作为系统函数库基座，为 `TB-Toolbox`、`DiffCheck`、`SyncBlock` 建立统一的公共调用层，减少重复实现，收口错误恢复、Undo、配置、宿主兼容与实体访问逻辑。

**首轮范围**

- `TB-Toolbox`
- `DiffCheck`
- `SyncBlock`

**明确不在首轮范围**

- `BR_LISP_DEV`
- `Network-Design-Tools`
- `atlisp-packages` 其他包的大规模迁移
- 命令体系的大规模重命名

## 一、设计原则

1. 模块调用函数，不重建已有公共函数。
2. 优先复用 `atlisp-lib`，只有缺失的能力才补到项目函数库。
3. 模块入口保留，业务算法保留，先替换底层重复能力。
4. 先收口恢复链路，再收口功能复用，避免“改完更难撤销”。
5. 所有修改都要配套对抗性验证，不能只验证正常流程。

## 二、分层方案

### 1. 系统函数库

直接复用 `atlisp-lib/src` 中现有稳定函数，优先使用以下命名空间：

- `entity:*`
- `point:*`
- `layer:*`
- `pickset:*`
- `block:*`

### 2. 项目函数库

新增仓库级统一内核层，职责只包括：

- 平台与宿主能力探测
- 安全 COM 调用包装
- `*error*` 接管与恢复
- Undo 生命周期
- sysvar 快照与恢复
- 配置文件路径与读写包装
- 统一边界框获取与兜底
- 选择集、实体、图层、图块的仓库级适配

### 3. 临时函数库

只允许放本轮迁移中的过渡函数：

- 仍有调用但尚未稳定抽象的包装函数
- 单模块私有、后续可能继续下沉的辅助函数

原则上第二轮继续消化，避免长期存在。

## 三、模块边界

### `TB-Toolbox`

- 保留：命令入口、DCL 绑定、业务流程、模块划分
- 迁移：重复的实体、点、图层、配置、Undo、错误恢复函数
- 风险点：加载路径、DCL 资源查找、批量打印模块质量较差

### `DiffCheck`

- 保留：差异签名算法、框合并逻辑、命令入口
- 迁移：边界框获取、图层准备、异常恢复、Undo 与 sysvar 管理
- 风险点：当前中断后环境污染，匿名块折叠导致漏检

### `SyncBlock`

- 保留：块同步业务流程、偏移投票逻辑
- 迁移：安全块校验、删除/复制事务封装、COM 失败处理、Undo/恢复
- 风险点：先删后拷导致目标块定义损坏，失败恢复不闭环

## 四、首轮优先统一的公共能力

1. 实体边界框获取
2. 选择集转列表
3. 图层存在性检查与创建
4. 图层解锁、打开、设为当前
5. 图块有效名与属性读取
6. sysvar 快照与恢复
7. Undo Begin/End
8. 安全 COM 调用
9. 安全退出与统一错误处理
10. 配置读写包装

## 五、首轮实施顺序

1. 梳理三个模块的函数映射表
2. 定义统一项目函数库文件结构
3. 建立统一核心加载入口
4. 先改 `TB-Toolbox` 基础层
5. 再改 `DiffCheck`
6. 再改 `SyncBlock`
7. 对三块逐一做对抗性静态审查与本地验证

## 六、对抗性验证清单

- 空选择集
- 非法对象类型
- 缺图层 / 缺样式 / 缺配置文件
- DCL 文件缺失
- COM 不可用或调用失败
- Undo 中途失败
- `CopyObjects` 失败
- 删除成功但复制失败
- 重复执行
- 半途中断
- 用户取消
- 撤销后状态恢复

## 七、成功标准

1. 三个首轮模块都改为优先调用统一函数库。
2. 旧重复函数显著减少，调用边界清晰。
3. 错误恢复与 Undo 链路统一。
4. 已知高风险路径至少在静态和本地层面完成对抗性验证。
5. 仍存在已知缺陷时，明确记录，不宣称 0 bug。
