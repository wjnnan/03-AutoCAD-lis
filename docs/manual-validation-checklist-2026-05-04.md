# AutoCAD Lisp 实机验证清单

日期：2026-05-04

适用范围：

- `TB-Toolbox`
- `DiffCheck`
- `SyncBlock`

目的：

- 验证统一函数库接入后，核心命令在真实 CAD 宿主内可以正常加载、执行、取消、恢复
- 验证异常输入、空输入、失败路径、重复操作路径不会污染环境
- 为“是否允许提交”提供人工复核证据

## 零、5 分钟快速开始

如果先只跑一轮最小冒烟验证，按下面顺序执行：

1. 命令行执行：
   - `(load "d:/My Code/Claude Code/03-AutoCAD-lisp/TB-Toolbox/load.lsp")`
   - `(load "d:/My Code/Claude Code/03-AutoCAD-lisp/DiffCheck/DiffCheck.lsp")`
   - `(load "d:/My Code/Claude Code/03-AutoCAD-lisp/SyncBlock/SyncBlock.lsp")`
2. 执行 `TBHELP`
3. 执行 `TB`
4. 执行 `DFC`，先做一次取消路径测试
5. 执行 `SyncNow`，先做一次空输入和非块输入测试

这一轮的最小通过标准：

1. 三个文件都能加载
2. `TBHELP` 可输出帮助
3. `TB` 能打开界面
4. `DFC` 取消后环境不脏
5. `SyncNow` 取消或错误输入后环境不脏

## 一、验证前准备

### 宿主环境

至少验证以下宿主中的 1 个主环境和 1 个兼容环境：

1. AutoCAD
2. 兼容 CAD 宿主（如 BricsCAD / GstarCAD / ZWCAD 中项目实际使用的版本）

### 基础准备

1. 将仓库目录加入支持文件搜索路径
2. 确认 `TB-Toolbox`、`unified-lib`、`DiffCheck`、`SyncBlock` 文件可访问
3. 准备三份测试图纸：
   - `A.dwg`：普通二维图元与文字
   - `B.dwg`：与 `A.dwg` 存在少量差异
   - `BLOCKS.dwg`：包含多个相似块定义、属性、不同图层颜色

### 通用观察项

每条测试都要记录以下结果：

1. 命令是否成功启动
2. 是否出现未处理报错
3. `Esc` / 取消后是否恢复 `CMDECHO`、`OSMODE`、`CLAYER`
4. 是否能通过一次 `UNDO` 回退本次操作
5. 是否出现残留半状态对象

## 二、TB-Toolbox 验证

### 1. 加载验证

步骤：

1. 执行 `(load "TB-Toolbox/load.lsp")`
2. 观察加载输出
3. 执行 `TBHELP`

预期：

1. 加载完成信息出现
2. 无未处理报错
3. `TBHELP` 正常输出版本、平台、命令信息

失败判据：

1. 根路径解析失败后直接中断宿主命令流
2. 加载过程中出现未定义函数错误
3. `TBHELP` 不可用

### 2. DCL 路径验证

步骤：

1. 执行 `TB`
2. 打开主界面
3. 关闭主界面
4. 执行 `TBSETTING`
5. 保存一次设置，再重新打开确认

预期：

1. 两个对话框均能打开
2. 不依赖当前图纸目录
3. 设置保存后再次打开仍可读取

失败判据：

1. 找不到 DCL
2. 对话框初始化失败
3. 保存设置后再次打开数据异常

### 3. 异常路径验证

步骤：

1. 在 `TB` 主界面打开后按 `Esc`
2. 连续重复执行 `TB`、关闭、再执行 `TBSETTING`
3. 在非标准图纸路径下重复加载 `load.lsp`

预期：

1. 无残留锁死对话框
2. 无重复绑定导致的命令异常
3. 无因路径变化导致的资源丢失

## 三、DiffCheck 验证

### 1. 正常差异检测

步骤：

1. 加载 `DiffCheck/DiffCheck.lsp`
2. 执行 `DFC`
3. 选择 `A.dwg` 区域为旧区域
4. 选择 `B.dwg` 对应区域为新区域

预期：

1. 能完成自动对齐
2. 在 `DIFF_CLOUD` 图层生成修订云线
3. 输出匹配数与变化数

失败判据：

1. `DIFF_CLOUD` 图层未正确准备
2. `REVCLOUD` 中断后命令卡死
3. 命令完成后系统变量未恢复

### 2. 空输入与取消路径

步骤：

1. 执行 `DFC`
2. 第一次选择直接回车
3. 再次执行 `DFC`
4. 第一次选择成功，第二次选择直接回车
5. 再次执行 `DFC`，在修订云生成阶段按 `Esc`

预期：

1. 每次取消后都有明确提示
2. 不会留下未闭合 `UNDO`
3. 不会污染当前图层和对象捕捉

### 3. 清理命令验证

步骤：

1. 先运行一次 `DFC`
2. 执行 `DFCC`
3. 再执行一次 `DFCC`

预期：

1. 第一次可清空云线
2. 第二次空清理不报错

## 四、SyncBlock 验证

### 1. 正常同步

步骤：

1. 加载 `SyncBlock/SyncBlock.lsp`
2. 执行 `SyncNow`
3. 选择主块
4. 窗选多个目标块

预期：

1. 输出主块名称
2. 每个目标块输出处理信息
3. 同步完成后输出 `Synced` 与 `Skipped`
4. 几何体复制后再删除旧对象，不出现半损坏块定义

失败判据：

1. `CopyObjects` 报错
2. 同步中断后目标块被删空
3. 同步完成但颜色、偏移明显异常

### 2. 非法输入路径

步骤：

1. 执行 `SyncNow`
2. 主对象选择空输入
3. 再执行 `SyncNow`
4. 主对象选择非块对象
5. 再执行 `SyncNow`
6. 主块选择成功，目标窗选直接取消

预期：

1. 每条路径都安全返回
2. 无未处理 COM 报错
3. 无环境污染

### 3. 目标块异常路径

步骤：

1. 构造一个损坏或不可解析的目标块
2. 执行 `SyncNow`
3. 同时包含正常目标块和异常目标块

预期：

1. 异常目标块被跳过
2. 正常目标块仍继续处理
3. `Skipped` 数量正确增加

### 4. 重复执行与撤销

步骤：

1. 连续两次执行 `SyncNow`
2. 每次完成后执行一次 `UNDO`
3. 再执行一次 `SyncNow`

预期：

1. 每次操作都能独立撤销
2. 不会出现重复叠加的幽灵对象
3. 不会出现第二次执行后块定义损坏

## 五、宿主兼容专项

### 1. COM 能力差异

步骤：

1. 在非 AutoCAD 宿主重复执行 `SyncNow`
2. 观察是否命中 COM 不可用提示

预期：

1. 若宿主不支持当前工作流，应给出明确提示并安全返回
2. 不得崩溃或卡死

### 2. `REVCLOUD` / `CMDACTIVE` 差异

步骤：

1. 在兼容宿主执行 `DFC`
2. 检查 `REVCLOUD` 过程是否能正常完成

预期：

1. 无命令流卡住
2. 无额外人工输入需求
